# 자동 점검 + 이메일 알림 (2026-11-03)

교수님 의견: 주기적으로 점검을 돌려서 사용자에게 이메일 등으로 알려 주면 좋겠다.

## 동작
- 계정(연결)마다 자동 점검 주기를 고른다: 끔(기본) / 매일 / 매주. 대시보드 카드의 "자동 점검·알림"에서 바꾼다.
- 작업자(`worker.py`)가 60초마다 `scheduler.run_due`를 불러, 마지막 스캔에서 주기가 지난 연결에 QUEUED 스캔을 만든다(수동 스캔과 같은 경로, 사용자당 동시 1개·하루 한도 그대로. 걸리면 조용히 건너뛰고 다음에 다시). 켜자마자 스캔이 없으면 1분 안에 첫 점검이 돈다.
- 스캔이 DONE이 되면 `notify.Notifier.scan_done`: 자동 점검이 켜진 연결이고, **같은 연결의 직전 완료 스캔에 없던 치명·높음 항목**이 있을 때만 로그인 이메일로 메일을 보낸다(같은 메일이 매일 오지 않게). 직전 스캔이 없으면 전부. 수동 스캔도 알림이 켜진 계정이면 같은 규칙으로 보낸다.
- 메일 내용: 계정 ID, 항목 제목(최대 10개)·리소스 개수, 결과 링크(`SITE_URL`). 리소스 이름·ARN은 넣지 않는다. 제목의 줄바꿈은 공백으로 바꾼다.
- 메일 실패는 스캔을 실패로 만들지 않고 로그만 남긴다.
- "테스트 메일 보내기" 버튼(`POST /api/notify/test`, 사용자당 1분에 1회)으로 SES 설정을 확인한다.
- API: `POST /api/connections/{id}/schedule {"schedule": "off|daily|weekly"}` (ACTIVE 연결만, 소유자만).
- 데모 모드(`DEMO_FIXTURE`)는 메일을 보내지 않고 서버 로그에 `DEMO MAIL`로 남긴다.

## 설정 (실서버)
- 메일은 Amazon SES(`sesv2:SendEmail`)로 보낸다. 비밀번호·SMTP 키가 필요 없고 인스턴스 Role만 쓴다.
- `MAIL_FROM`(보내는 주소)이 비어 있으면 알림 기능은 꺼진다(화면에 "메일 발송 미설정" 안내).
- **SES 샌드박스**: 새 계정은 샌드박스라 **보내는 주소와 받는 주소가 모두 SES에서 확인된 이메일**이어야 한다(콘솔 SES → Identities → Create identity → Email address → 받은 메일의 링크 클릭, 서울 리전). 시연용으로는 본인 주소를 보내는 주소이자 받는 주소로 쓰면 된다. 샌드박스 해제(Production access)는 AWS 심사가 필요해 하지 않았다.
- `infra/ec2.yaml`에 `MailFrom` 파라미터 추가: `.env`의 `MAIL_FROM`, `SITE_URL`을 채우고 인스턴스 Role에 그 주소 하나에 대한 `ses:SendEmail`만 허용한다.

## 이미 배포된 서버에 적용하는 순서 (사용자 몫)
1. PR 병합 후 EC2에서 `git pull`.
2. **DB 마이그레이션 한 번**: `db/migrations/2026-11-03-schedule.sql`(connections에 `schedule` 열). 앱 계정은 ALTER 권한이 없어 root로 실행한다(파일 머리말에 명령). 새 코드를 띄우기 전에 한다 — 열이 없으면 연결 조회가 실패한다.
3. SES에서 이메일 주소 확인(위).
4. 스택 업데이트로 `MailFrom` 지정(IAM 정책만 바뀐다. UserData 변경은 이미 떠 있는 인스턴스에 반영되지 않으므로 `.env`에 `MAIL_FROM=...`, `SITE_URL=https://<이름>.duckdns.org`를 직접 추가한다).
5. `docker compose up -d --build` 후 대시보드에서 "테스트 메일 보내기".

## 안 한 것 / 한계
- 비용 임계값 알림, Slack·텔레그램 등 다른 채널, 사용자별 수신 주소 변경(로그인 이메일로만 보낸다).
- 연결이 깨진(Role 삭제 등) 계정의 자동 점검은 주기마다 실패만 기록하고 알리지 않는다.
- 스캔은 한 번에 하나씩 처리하므로 계정이 많으면 점검 시각이 밀린다.
- 메일은 평문이다. 결과 링크는 로그인해야 열린다.
